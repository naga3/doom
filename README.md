# チェックボックスで描く DOOM

1ドット = `<input type="checkbox">` 1個。チェックの有無が白黒のピクセルで、
`transform: scale()` で1個の大きさを変えると1bit より細かい濃淡も出せる、という表示装置の上に
Wolf3D 方式のレイキャスタを載せたものです。canvas も WebGL も使っていません。

- `index.html` — 歩けるデモ。解像度とモードを切り替えて見比べられます
- `bench.html` — 描画コストの計測ページ

## 動かす

```sh
npm start        # http://localhost:4174
```

WASD で移動、左右キーかマウス（画面クリックでポインタロック）で旋回。

## 3つのモード

壁の高さはレイキャスタが小数で返します。それをチェックボックスの格子にどう落とすかが違います。

| モード | 壁の内側 | 壁の輪郭 | 見た目 |
|---|---|---|---|
| **A** | `checked` のベタ塗り | 行に四捨五入 | カリカリのドット絵。歩くと輪郭が1マス単位で跳ねる |
| **B** | `checked` のベタ塗り | 端数ぶん `scale()` で縮める | 輪郭だけが滑らかに動く。内側は A と同じ |
| **C** | 全セルの大きさで明暗 | 同じ | 網点（ハーフトーン）。新聞写真の質感 |

明暗は A / B ではベイヤー 4x4 の順序ディザ、C では大きさそのもので表します。

## 計測結果

```sh
node bench/measure.cjs 90
```

WSL2 + Chromium、実画面（ヘッドレスではない）、90フレームの中央値。

| 解像度 | セル数 | A | B | C |
|---|---|---|---|---|
| 64 x 40 | 2,560 | 60.0 fps | 60.0 fps | 59.3 fps |
| 96 x 60 | 5,760 | 59.9 fps | 54.1 fps | 32.4 fps |
| 128 x 80 | 10,240 | 58.7 fps | 34.8 fps | 19.9 fps |
| 160 x 100 | 16,000 | 47.1 fps | 22.9 fps | 12.3 fps |

**`checked` の切り替えは安い。インラインの `transform` は高い。**
A は 10,240 セルでも 60fps に届きます。一方 B は、1フレームに増える書き込みが
150個ほどしかないのに 128x80 で fps がほぼ半分になります。

JS 側の時間（`render ms` + `flush ms`）は最大でも 5ms 弱しかありません。
時間はブラウザの style 再計算と再描画に出ていて、`performance.now()` では捕まりません。
判断に使えるのは fps だけです。

### 原因は「大きさの種類」ではない

大きさの量子化段数を 1 / 2 / 4 / 16 段に変えても、B の fps は動きませんでした（128x80 で 33.5〜35.0 fps）。
段数1はスケール指定が実質なくなる設定なので、**ネイティブ部品を新しい寸法で描き直すコストではなく、
インラインスタイルに触ること自体のコスト**だと分かります。
しかも1回あたりの重さはセル数とともに増える（96x60 で約 17µs、160x100 で約 97µs）ため、
1個書き換えるたびに格子全体を巻き込む再計算が起きていると考えられます。

### 決まったこと

- **A なら 128 x 80**（58.7 fps）。解像度を取るならこれ
- **B なら 96 x 60**（54.1 fps）。輪郭の滑らかさを取るならこれ
- **C は 64 x 40 まで**（59.3 fps）。網点は解像度を1段以上犠牲にする

解像度と輪郭の滑らかさはトレードします。B が A に対してほぼ無料になる、という当初の見込みは外れました。

### 未検証

インラインスタイルではなく、あらかじめ用意した CSS クラス（`.c0`〜`.c16`）の付け替えで
大きさを変えたらコストが変わるかは、まだ試していません。これが効けば B の値段は下がります。

## 構成

| ファイル | 役割 |
|---|---|
| `src/grid.js` | チェックボックスの格子。差分だけ DOM に書く |
| `src/raycast.js` | マップと DDA レイキャスト |
| `src/scene.js` | レイキャスト結果を 1bit のフレームバッファに落とす。モードの違いはここだけ |
| `src/camera.js` | カメラ、当たり判定、計測用の自動歩行 |
| `src/engine.js` | 上をまとめた実行系。デモと計測で共有 |
| `src/main.js` | デモの入力とループ |
| `src/bench.js` | 計測ページ。`window.__bench` を公開 |
| `bench/measure.cjs` | Playwright で Chromium を回して表を出す |

### 格子を速く保つための約束

- 要素は起動時に1回だけ作る。以降は差分のあるセルだけ触る
- 消えているセルは `visibility: hidden`。未チェックの枠線が見えると黒が濁る
- 格子全体は1枚の `transform: scale()` で縮める。セルごとに `width` を変えると格子が崩れる
- 格子には `aria-hidden` と `tabIndex = -1`。1万個のタブ停止点とクリックによる画面の破壊を防ぐ
